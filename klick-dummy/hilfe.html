Erste Schritte

  1. Such dir im Katalog eine Challenge aus und lies die Aufgabe.
  2. Löse sie mit deinen eigenen Werkzeugen auf deinem Rechner.
  3. Reiche deine Lösung im Tab Einreichen der Challenge ein.
  4. Die Plattform prüft deine Lösung und zeigt dir das Ergebnis und deinen Lösungsstatus.

Lösungsvertrag für Code

Deine Lösung ist ein HTTP-Service in Java. Damit die Plattform ihn prüfen kann, muss er diese Regeln erfüllen:

JavaJava 21; gebaut wird mit Maven
Buildmvn -o -q package erzeugt genau ein ausführbares JAR unter target/. Der Build läuft ohne Netzwerk.
Startjava -jar <jar>; den Port liest dein Service aus der Umgebungsvariable PORT.
Health-CheckGET /health antwortet innerhalb von 30 Sekunden nach dem Start mit 200.

Starter-Template

Das allgemeine Starter-Template enthält eine passende pom.xml und einen Beispiel-Service, der den Lösungsvertrag erfüllt. Für eine konkrete Challenge nimmst du besser deren Starter-Code: Er enthält zusätzlich die Libraries dieser Challenge.

Erlaubte Libraries

Jede Challenge legt fest, welche Libraries und Maven-Plugins deine Lösung nutzen darf. Du findest die Liste im Tab Libraries der Challenge. Abhängigkeiten dieser Libraries sind automatisch erlaubt.

Weil dein Build ohne Netzwerk läuft, schlägt er fehl, wenn deine pom.xml eine andere Library oder ein anderes Plugin verwendet. Die Ergebnisseite nennt dir dann, welche Library nicht erlaubt ist.

Einreichen per git push

Die Plattform nimmt deinen Commit per git push entgegen. Sie speichert kein Repository: Deine History bleibt bei dir.

git remote add submit https://coding-challenges.example/challenges/<challenge-id>.git
git push submit main

Als Passwort verwendest du dein Push-Token. Git bestätigt die Einreichung mit dem Commit und einem Link zur Ergebnisseite. Reichst du ein, während deine vorherige Einreichung noch geprüft wird, wird diese Prüfung abgebrochen.

Wenn ein Push abgelehnt wird

MeldungWas du tun kannst
Ungültiges Push-TokenErzeuge ein neues Token und aktualisiere es in deinem Credential-Manager.

Genau ein Branch pro PushPushe nur einen Branch, z. B. git push submit main.
Challenge archiviert oder gesperrtFür diese Challenge sind keine Einreichungen mehr möglich.

Ergebnisse verstehen

ErgebnisBedeutung
BestandenDer Wert stimmt bzw. alle Tests sind bestanden.
Nicht bestandenDer Wert stimmt nicht bzw. mindestens ein Test ist fehlgeschlagen oder hat zu lange gedauert.
FehlerDie Prüfung konnte nicht durchgeführt werden, z. B. wegen eines Build-Fehlers oder weil dein Service nicht startete.

Öffentliche Tests zeigen dir bei einem Fehler Request, erwartete und tatsächliche Response. Von versteckten Tests siehst du nur Name und Status; für sie gibt es auch kein Service-Log.

Dein Lösungsstatus richtet sich immer nach deiner neuesten abgeschlossenen Einreichung. Ändert der Autor die Challenge, bleiben deine bisherigen Ergebnisse erhalten; du siehst, zu welcher Version sie gehören.

Einreichungs-Limit

Jede Challenge erlaubt nur eine bestimmte Zahl von Einreichungen pro 15 Minuten. Erreichst du das Limit, sagt dir die Plattform, ab wann du wieder einreichen kannst. Als Gast über einen Teilen-Link gilt zusätzlich ein gemeinsames Limit für alle Gäste dieses Links.
